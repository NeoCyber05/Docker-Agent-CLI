# Database Deployment — Image Knowledge Base

A reference skill for the Docker Agent CLI coding agent. It provides exact, copy-paste-ready configuration for deploying database containers. This skill complements `requiredSecrets.ts` (which only covers postgres, mysql, mariadb, mongo, redis) by adding Elasticsearch, Memcached, ClickHouse, and MinIO, and by providing much richer per-image metadata.

## How to Use This Skill

When generating a `plan_stack` call that includes a database service, look up the relevant engine below and use the recommended image, env vars, healthcheck, volume path, and port. Do not guess — use the values documented here.

---

## 1. PostgreSQL

| Field | Value |
|---|---|
| **Image** | `postgres:16-alpine` |
| **Default port** | `5432` |
| **Data volume** | `/var/lib/postgresql/data` |

**Required env vars:**
- `POSTGRES_PASSWORD` — superuser password (auto-generated by requiredSecrets)

**Recommended env vars:**
- `POSTGRES_USER` — superuser name (default: `postgres`)
- `POSTGRES_DB` — default database name (default: same as `POSTGRES_USER`)
- `POSTGRES_INITDB_ARGS` — extra `initdb` flags (e.g. `--data-checksums`)

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-postgres}"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 30s
```

**Init scripts:** Mount `.sql`, `.sql.gz`, or `.sh` files into `/docker-entrypoint-initdb.d/`. They run once on first container start, in filename order.

**Performance tuning env vars:**
- `POSTGRES_SHARED_BUFFERS`, `POSTGRES_WORK_MEM` — not supported natively; use a custom `postgresql.conf` mounted to `/etc/postgresql/postgresql.conf` with `command: -c 'config_file=/etc/postgresql/postgresql.conf'`.

**Security:** Keep on an internal network. Bind port to `127.0.0.1:5432:5432` for dev only; omit `ports` entirely in production.

## 2. MySQL

| Field | Value |
|---|---|
| **Image** | `mysql:8.4-oracle` |
| **Default port** | `3306` |
| **Data volume** | `/var/lib/mysql` |

**Required env vars:**
- `MYSQL_ROOT_PASSWORD` — root password (auto-generated by requiredSecrets)

**Recommended env vars:**
- `MYSQL_DATABASE` — create this database on first start
- `MYSQL_USER` + `MYSQL_PASSWORD` — create a non-root user with full access to `MYSQL_DATABASE`
- `MYSQL_ALLOW_EMPTY_PASSWORD` — set to `yes` only for throwaway dev containers

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 30s
```

**Init scripts:** Mount to `/docker-entrypoint-initdb.d/`. Supports `.sql`, `.sql.gz`, `.sh`.

**Security:** Never expose port 3306 to the public internet. Use `MYSQL_USER` instead of root for application connections.

## 3. MariaDB

| Field | Value |
|---|---|
| **Image** | `mariadb:11-noble` |
| **Default port** | `3306` |
| **Data volume** | `/var/lib/mysql` |

**Required env vars:**
- `MARIADB_ROOT_PASSWORD` — root password (auto-generated by requiredSecrets)

**Recommended env vars:**
- `MARIADB_DATABASE` — auto-create database
- `MARIADB_USER` + `MARIADB_PASSWORD` — non-root user
- `MARIADB_AUTO_UPGRADE=1` — auto-upgrade data files on major version bumps

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 30s
```

> MariaDB 10.4+ ships a `healthcheck.sh` script. Use it instead of `mysqladmin ping` — it checks InnoDB readiness.

**Init scripts:** Same as MySQL — `/docker-entrypoint-initdb.d/`.

## 4. MongoDB

| Field | Value |
|---|---|
| **Image** | `mongo:7` |
| **Default port** | `27017` |
| **Data volume** | `/data/db` |

**Required env vars:**
- `MONGO_INITDB_ROOT_USERNAME` — admin username (default: none, no auth)
- `MONGO_INITDB_ROOT_PASSWORD` — admin password (auto-generated by requiredSecrets)

**Recommended env vars:**
- `MONGO_INITDB_DATABASE` — run init scripts against this database

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 30s
```

> For MongoDB 5.x and below, use `mongo` instead of `mongosh`.

**Init scripts:** Mount `.js` or `.sh` files to `/docker-entrypoint-initdb.d/`.

**Security:** Always set both `MONGO_INITDB_ROOT_USERNAME` and `MONGO_INITDB_ROOT_PASSWORD`. Without them, MongoDB starts with no authentication.

## 5. Redis

| Field | Value |
|---|---|
| **Image** | `redis:7-alpine` |
| **Default port** | `6379` |
| **Data volume** | `/data` |

**Required env vars:** None.

**Recommended configuration — use `command` instead of env vars:**
```yaml
command: redis-server --appendonly yes --requirepass "${REDIS_PASSWORD}"
```

To enable persistence, always pass `--appendonly yes`. For password protection, use `--requirepass`.

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD", "redis-cli", "ping"]
  interval: 10s
  timeout: 3s
  retries: 5
  start_period: 5s
```

> If `requirepass` is set, use: `["CMD-SHELL", "redis-cli -a $REDIS_PASSWORD ping"]`

**Security:** Redis has no authentication by default. Always set `--requirepass` in production. Never expose port 6379 to the public.

## 6. Elasticsearch

| Field | Value |
|---|---|
| **Image** | `elasticsearch:8.15.0` (Docker Hub official) |
| **Default port** | `9200` (HTTP), `9300` (transport) |
| **Data volume** | `/usr/share/elasticsearch/data` |

**Required env vars:**
- `ELASTIC_PASSWORD` — password for the `elastic` superuser (ES 8.x+ enables security by default)

**Recommended env vars:**
- `discovery.type=single-node` — required for single-node dev setups; skips cluster bootstrap
- `xpack.security.enabled=true` — enabled by default in 8.x; set to `false` only for local dev
- `ES_JAVA_OPTS=-Xms512m -Xmx512m` — JVM heap size; set to 50% of available container memory
- `cluster.name` — custom cluster name

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD-SHELL", "curl -fsSL http://localhost:9200/_cluster/health || exit 1"]
  interval: 15s
  timeout: 10s
  retries: 5
  start_period: 60s
```

> For secured clusters: `curl -fsSL -u elastic:${ELASTIC_PASSWORD} http://localhost:9200/_cluster/health`

**Note:** Elasticsearch requires `vm.max_map_count=262144` on the host. This is a host-level setting, not a container config.

**Security:** Use `xpack.security.enabled=true` in production. Set `ELASTIC_PASSWORD` via env_file.

## 7. Memcached

| Field | Value |
|---|---|
| **Image** | `memcached:1.6-alpine` |
| **Default port** | `11211` |
| **Data volume** | None (in-memory only, no persistence) |

**Required env vars:** None.

**Configuration via command args:**
```yaml
command: memcached -m 256 -c 1024
```
- `-m 256` — max memory in MB (default: 64)
- `-c 1024` — max simultaneous connections (default: 1024)

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD-SHELL", "echo stats | nc localhost 11211 | grep -q pid"]
  interval: 10s
  timeout: 3s
  retries: 5
  start_period: 5s
```

> Alpine images may not include `nc`. Alternative: install `netcat-openbsd` in a custom Dockerfile, or use the `memcached:1.6` (Debian) image which includes it.

**Security:** Memcached has no authentication. It must never be exposed publicly. Always place on an internal-only network.

## 8. ClickHouse

| Field | Value |
|---|---|
| **Image** | `clickhouse/clickhouse-server:24-alpine` |
| **Default port** | `8123` (HTTP), `9000` (native TCP) |
| **Data volume** | `/var/lib/clickhouse` |
| **Logs volume** | `/var/log/clickhouse-server` |

**Recommended env vars:**
- `CLICKHOUSE_USER` — default user (default: `default`)
- `CLICKHOUSE_PASSWORD` — password for the default user
- `CLICKHOUSE_DB` — auto-create database
- `CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1` — allow SQL-based user management

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD-SHELL", "wget --no-verbose --tries=1 --spider http://localhost:8123/ping || exit 1"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 15s
```

**Init scripts:** Mount `.sql` files to `/docker-entrypoint-initdb.d/`.

**Security:** Set `CLICKHOUSE_PASSWORD` — ClickHouse allows passwordless access by default.

## 9. MinIO (S3-Compatible Object Storage)

| Field | Value |
|---|---|
| **Image** | `minio/minio:latest` (MinIO recommends `:latest` — they use immutable release tags under the hood) |
| **Default port** | `9000` (API), `9001` (Console UI) |
| **Data volume** | `/data` |

**Required env vars:**
- `MINIO_ROOT_USER` — admin username (min 3 chars)
- `MINIO_ROOT_PASSWORD` — admin password (min 8 chars)

**Command:**
```yaml
command: server /data --console-address ":9001"
```

**Healthcheck:**
```yaml
healthcheck:
  test: ["CMD", "mc", "ready", "local"]
  interval: 15s
  timeout: 5s
  retries: 5
  start_period: 10s
```

> Alternative healthcheck: `["CMD-SHELL", "curl -fsSL http://localhost:9000/minio/health/live"]`

**Security:** Always set `MINIO_ROOT_USER` and `MINIO_ROOT_PASSWORD`. Never use the legacy `MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` — they are deprecated.

## General Best Practices

### Named Volumes for All Stateful Services
Always declare named volumes in the top-level `volumes:` section. Never rely on anonymous volumes or container-internal storage for data you need to keep.

```yaml
volumes:
  postgres-data:
  redis-data:
  mongo-data:
```

### Network Isolation
Database services should not be on the same network as public-facing services. Use a dedicated internal network:

```yaml
networks:
  backend:
    internal: true   # no external/internet access

services:
  api:
    networks: [frontend, backend]
  db:
    networks: [backend]  # only reachable from api
```

### Backup Strategies

**Volume-based (generic):**
```bash
docker run --rm -v postgres-data:/data -v $(pwd):/backup alpine \
  tar czf /backup/postgres-backup.tar.gz -C /data .
```

**pg_dump (PostgreSQL):**
```bash
docker compose exec db pg_dump -U postgres mydb > backup.sql
```

**mongodump (MongoDB):**
```bash
docker compose exec mongo mongodump --archive=/data/backup.gz --gzip
```

### Restart Policy
Always set `restart: unless-stopped` for database services to survive host reboots and Docker daemon restarts.

### Resource Limits
Set memory limits for JVM-based engines (Elasticsearch, ClickHouse) to prevent OOM kills:

```yaml
deploy:
  resources:
    limits:
      memory: 2G
```

Match JVM heap (`ES_JAVA_OPTS`) to ~50% of the container memory limit.

## Anti-Patterns

| Anti-Pattern | Why It's Bad | Do This Instead |
|---|---|---|
| Using `:latest` tag | Breaks reproducibility; silent breaking changes | Pin to major+minor: `postgres:16-alpine` |
| Hardcoded passwords in `environment` | Visible in `docker inspect`, compose file, logs | Use `env_file` pointing to a `.env` file (gitignored) |
| No volume for data directory | All data lost on container restart | Always mount a named volume to the data path |
| Exposing DB port to `0.0.0.0` | Anyone on the network can connect | Bind to `127.0.0.1` or omit `ports` entirely |
| No healthcheck | `depends_on` won't wait for readiness | Always add a healthcheck; use `condition: service_healthy` |
| Running as root | Compromise escalation risk | Use images that run as non-root (alpine variants) |
| Skipping `start_period` | Container marked unhealthy during init | Set `start_period` to cover the longest expected startup |
| Using `MYSQL_` env vars for MariaDB | MariaDB 10.6+ prefers `MARIADB_` prefix | Use `MARIADB_ROOT_PASSWORD`, not `MYSQL_ROOT_PASSWORD` |
