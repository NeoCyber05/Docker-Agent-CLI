# Project Structure

## Top-Level Layout

```
Docker-Agent-CLI/
├── src/                  # All application source code
├── tests/                # Shared test infrastructure (mocks, integration tests)
├── dist/                 # Compiled output (gitignored, generated by tsup)
├── docs/                 # Design documents and planning notes
├── .docker-agent/        # Runtime state directory (created at runtime in cwd)
├── .kiro/                # Kiro specs and steering files
└── .claude/              # Claude AI planning notes
```

## `src/` Directory

```

├── query.ts              # Core ReAct loop: drives LLM ↔ tool calls iteratively
├── Tool.ts               # Tool interface + ToolContext type definitions
├── tools.ts              # Registers and exports all tools as an array
├── slashCommands.ts      # Handles /stacks, /status, /destroy, /provider, etc. in REPL
├── config.ts             # User config loading, provider resolution, path helpers
├── context.ts            # LoopContext assembly (wires ToolContext + permission callbacks)
├── loopContext.ts        # LoopContext type definition
│
├── components/           # Ink (React) UI components
│   ├── WelcomeBanner.tsx
│   ├── MessageList.tsx
│   ├── PromptInput.tsx
│   ├── PlanPreview.tsx       # Shows YAML diff + secrets summary before approval
│   ├── PermissionDialog.tsx
│   ├── SecretsInputDialog.tsx
│   ├── TypedConfirmDialog.tsx
│   ├── ModelPickerDialog.tsx
│   ├── ApiKeyInputDialog.tsx
│   ├── FormattedText.tsx
│   ├── Header.tsx
│   └── Footer.tsx
│
├── screens/
│   └── REPL.tsx          # Top-level Ink screen: composes all components, drives QueryEngine
│
├── tools/                # One file per agent tool
│   ├── planStack.ts          # Generates Compose YAML plan (no side effects)
│   ├── applyStack.ts         # Writes YAML and runs `docker compose up` with health gate
```

## Architecture Layers

```
CLI entry (cli.ts)
  └── main.ts            ← arg parsing, dependency wiring
        └── REPL.tsx     ← Ink UI; drives QueryEngine turn-by-turn
              └── QueryEngine.ts  ← turn state, permission gates, session persistence
                    └── query.ts  ← ReAct loop: LLM ↔ tools
                          ├── services/api/   ← LLM provider calls
                          └── tools/          ← Docker operations (plan, apply, destroy, …)
                                └── services/docker/  ← Dockerode + compose CLI
                                └── state/            ← File-based state persistence
```

## Naming Conventions

- **Tool files**: `camelCase` noun+verb (e.g., `planStack.ts`, `applyStack.ts`); export a `const` with the same name matching the `Tool.name` string
- **Component files**: `PascalCase.tsx`
- **Type files**: `camelCase.ts` inside `src/types/`
- **Test files**: `*.test.ts(x)` co-located under `__tests__/` in the same directory as the source file, or under `tests/` for integration tests
- **Stack names**: validated as `/^[a-z][a-z0-9_-]{0,62}$/`

## Runtime State (`.docker-agent/` in cwd)

```
.docker-agent/
├── stacks/               # Active stack YAML files (<name>.yaml)
│   └── .archive/         # Timestamped + latest archived copies on destroy
├── secrets/              # Generated .env files (<stackName>-<service>.env, mode 0o700)
├── locks/                # Per-stack mutex lock files
├── sessions/             # Persisted conversation transcripts (JSON)
├── logs/                 # Runtime logs
└── history.json          # Append-only audit log (newline-delimited JSON)
```
